# אפליקציית המסע לבודפשט: צ׳קליסט לפני הטיסה ומה עושים אם

האפליקציה היא דף אחד (`trip/index.html`) שמתפרסם ב-GitHub Pages. הנתונים נשמרים ב-Firestore, בפרויקט `budapest-983e4`.
חוקי האבטחה (`firestore.rules`) לא מתפרסמים לבד: מדביקים אותם ידנית בקונסול של Firebase.

## שלב 1: פרסום השינויים של הסבב הזה (פעם אחת, לפי הסדר)

הסדר חשוב. החוקים החדשים דורשים שכל מחיקה תשמור עותק בסל המחזור, וזה קורה רק בגרסה החדשה של האפליקציה.
אם מפרסמים את החוקים לפני האפליקציה, מחיקות ייכשלו (תופיע הודעה "המחיקה נכשלה") עד שהאפליקציה תתעדכן.

- [ ] ממזגים את השינויים ל-main. GitHub Pages מתעדכן תוך 1–3 דקות.
- [ ] פותחים את האפליקציה בטלפון ומרעננים. ב"עוד ← הגדרות" צריך להופיע הכרטיס "גיבוי וייצוא". אם לא מופיע, סוגרים את האפליקציה לגמרי ופותחים מחדש.
- [ ] לוחצים **"גיבוי מלא (קובץ)"** ושומרים את הקובץ בתיקיית הדרייב של המסע.
- [ ] מפרסמים את החוקים: Firebase Console ← Firestore ← Rules. מדביקים את כל התוכן של `firestore.rules`. לפני "Publish" בודקים ב-Rules Playground:
  - מחיקה של `trips/<המפתח>/tasks/x` **בלי** עותק בסל: צריכה להיכשל.
  - קריאה של `trips/<המפתח>/tasks/x`: צריכה להצליח.
- [ ] אחרי הפרסום: מוחקים פריט ניסיון באפליקציה ("משימה לבדיקה"), רואים שהוא מופיע ב"הגדרות ← נמחקו לאחרונה", ומשחזרים.
- [ ] משחק הטריוויה (הדף הראשי) ממשיך לעבוד: פותחים משחק לבד ומשחקים שאלה אחת. החוקים שלו לא השתנו, אבל זה אותו קובץ.

**חזרה לאחור:** אם משהו נשבר אחרי פרסום החוקים, מדביקים בקונסול את הגרסה הקודמת של `firestore.rules` מ-GitHub (ההיסטוריה של הקובץ) ומפרסמים. הנתונים לא נפגעים מהחלפת חוקים.

## שלב 2: שבוע לפני הטיסה (עד 12.11)

- [ ] "ייצוא לאקסל" ופתיחה במחשב. בודקים שהגיליון "סיכום" מראה את אותם מספרים כמו מסך הכסף (עמודה "לפי הגיליונות" מול "באפליקציה").
- [ ] "ספירת קופה" אצל שלומי ואיציק. אם יש פער, מבררים עכשיו ולא בבודפשט.
- [ ] בקופות, כל מי שמופיע תחת "שילם מכיסו · להחזיר לו" מקבל החזר או רישום.
- [ ] אין משתתפים תחת "שולם, אבל לא רשום אצל מי הכסף".
- [ ] כל אחד מהצוות (שלומי, איציק, יעל):
  - [ ] פותח את האפליקציה מהקישור עם `#k=…` ומוסיף אותה למסך הבית (בספארי: שיתוף ← "הוספה למסך הבית". בכרום: ⋮ ← "הוספה למסך הבית").
  - [ ] פותח אותה פעם אחת מהאייקון עם אינטרנט, כדי שהטלפון ישמור עותק.
  - [ ] **בדיקת טיסה:** מצב טיסה ← פותחים מהאייקון. צריכים לראות את הלו״ז, החדרים והמשתתפים, ופס צהוב "אין קליטה". מסמנים משימה, מבטלים את מצב הטיסה, ובודקים שהסימון הגיע לטלפון של מישהו אחר.
- [ ] הקישור של הצוות (`#k=…`) שמור אצל כל אחד גם מחוץ לאפליקציה: בהודעה לעצמו בוואטסאפ או בפתקים. **לא** בקבוצת המשתתפים.

## שלב 3: יום לפני הטיסה (18.11)

- [ ] "גיבוי מלא (קובץ)" ← לדרייב. זה הגיבוי שחוזרים אליו אם משהו משתבש במסע.
- [ ] "ייצוא לאקסל" ← לדרייב, ומורידים עותק גם לטלפון (קבצים), כדי שיהיה זמין בלי אינטרנט.
- [ ] בכל הטלפונים של הצוות: פותחים את האפליקציה עם אינטרנט ומחכים שהכל ייטען (המונים בבית מתמלאים). כך העותק בטלפון עדכני.
- [ ] בודקים שבמסך "ספירת נוכחות" מופיעים כל הנוסעים לפי האוטובוס.
